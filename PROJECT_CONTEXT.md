## 1. What this is

A local, Docker-based **Apache Spark + Apache Iceberg lab** for data engineering and ML experiments, designed for a MacBook (Apple Silicon or Intel).

| Service | Image | Role |
|---|---|---|
| `spark-jupyter` | built from `Dockerfile` | Spark 4.1.2 + JupyterLab + PySpark + PyIceberg + data/ML libraries |
| `iceberg-rest` | `apache/iceberg-rest-fixture` | Iceberg REST catalog (in-memory by default) |
| `minio` | `minio/minio` | S3-compatible storage holding Iceberg data files |
| `minio-init` | `minio/mc` | One-shot: creates the `warehouse` bucket |

Sample workload: BTS On-Time Performance airline data loaded into Iceberg (`local.airline.*`) and a flight-delay classification notebook using Spark MLlib.

### Target versions

| Component | Version | Notes |
|---|---|---|
| Apache Spark | 4.1.2 | Scala 2.13 |
| Apache Iceberg | 1.12.0 (build arg) | 1.11.0 was the first release with Spark 4.1 support; runtime artifact is `iceberg-spark-runtime-4.1_2.13` |
| Python | 3.11 | |
| OpenJDK | 17 | |
| PyIceberg | 0.11.1 | **Independent 0.x versioning. Never pin to 1.x.** |

Iceberg's JARs (`iceberg-spark-runtime` and `iceberg-aws-bundle`) are downloaded **at image build time** into `$SPARK_HOME/jars`, not at runtime. No `spark.jars.packages` is used.

## 4. How we got here (decision log)

1. **Standalone Spark + JupyterLab image first.** Python 3.11 slim, OpenJDK 17, Spark tarball, JupyterLab and a data-science stack, `local[*]` mode.
2. **Multi-arch by design.** No `--platform` flag; nothing in the Dockerfile names a CPU architecture.
3. **Three early failures fixed** (see §5): `ENV` rejecting `$(...)`, Jupyter refusing root, deprecated `NotebookApp` keys. Also dropped the obsolete compose `version:` key.
4. **Host folder mount** so notebooks persist outside the container (needs Docker Desktop file-sharing permission on macOS).
5. **Delta Lake tried, then dropped for Iceberg.** Delta failed with `DATA_SOURCE_NOT_FOUND`: the `delta-spark` pip package doesn't ship the JVM JARs. The user chose Iceberg as the table format, so Delta was removed entirely.
6. **Iceberg first via a local Hadoop catalog**, using `spark.jars.packages` to fetch the runtime JAR on first start.
7. **Merged with a second project** (Iceberg + MinIO) into one stack: Spark/Jupyter + REST catalog + MinIO.
8. **Real dataset and ML added:** BTS airline data into `local.airline`, then the delay-model notebook.
9. **Dependency and permission hardening** after failures (PyIceberg versioning, `fsspec`/`s3fs` pins, conf-dir ownership).
10. **2026-11-19 regeneration** (this version). Changes vs. earlier scaffolding:
    - `JAVA_HOME` made architecture-neutral (symlink), replacing a hardcoded `arm64` fallback.
    - Host path made configurable (`WORK_DIR`) instead of hardcoded `/Users/anoel/work`.
    - Iceberg JARs baked in at build time (works offline, faster first start) instead of `spark.jars.packages`.
    - Runs as non-root user; `--allow-root` only if uid is 0.
    - `SPARK_DRIVER_MEMORY` now actually takes effect (earlier it was set in compose but never read by Spark).
    - Added `.env.example`, `requirements.txt`, `Makefile`, `.gitignore`, data mount, and a `PyIceberg` check in the smoke test.

## 5. Gotchas and known fixes

Read before debugging any setup or notebook failure.

### Docker and permissions
| Symptom | Cause | Fix |
|---|---|---|
| `Syntax error - can't find =` on `ENV JAVA_HOME=$(...)` | `ENV` can't run shell | Resolve in a `RUN` step; expose via a symlink |
| `Running as root is not recommended. Use --allow-root` | Jupyter refuses root | Run as non-root (done); `--allow-root` only for uid 0 |
| Warnings about `NotebookApp.token` | Keys moved in Jupyter 2.x | Use `ServerApp.*` / `IdentityProvider.token` |
| `spark-defaults.conf` unreadable/unwritable | Ownership after `USER` switch | `COPY`/`chmod` before `USER`; `chown` `$SPARK_HOME/conf` |
| Mounted folder empty in Jupyter | Docker Desktop lacks file sharing | Settings → Resources → File Sharing |
| Compose warns `version is obsolete` | Compose v2 ignores it | Don't include it |
| `SPARK_DRIVER_MEMORY` has no effect | Spark conf can't read env vars | `entrypoint.sh` writes it into `spark-defaults.conf` |

### Dependencies
- **PyIceberg is 0.x**, independent of Iceberg's 1.x. Pin `pyiceberg==0.11.1`.
- Pin **`fsspec` and `s3fs` to `2024.12.0` together**.
- **No `[s3fs]` extra** on pyiceberg (dependency conflicts).
- `delta-spark` on pip does not include the JVM JARs (historical).

### Spark 4.x ML
- `GBTClassifier` does not accept `probabilityCol`.
- `StringIndexer(handleInvalid="keep")`, never `"skip"`.
- Create `DepHour`, `label`, `classWeight` **before** `randomSplit`.

### Data and ETL
- Drop and recreate Iceberg tables before loading (no duplicate rows on re-run).
- `nullValue="NA"` when reading BTS CSVs.
- File is `plane_types.csv`, not `plane-data.csv`.

## 6. Verification status and known limitations

### What was verified (2026-11-19, in a sandbox)
- `docker compose config` parses `docker-compose.yml`; `bash -n` passes on `entrypoint.sh`.
- All notebooks validate with `nbformat`; every code cell passes a Python syntax check.
- **Notebook 05 executed end-to-end on PySpark 4.1.2** against synthetic flight data: all four models, the cross-validator, evaluators, pandas summary and plot. (AUC ≈ 0.52 there only because the synthetic data is random.)
- Notebook 04's analysis cells (null rates, carrier join, monthly chart) executed on the same synthetic data.
- Iceberg artifact naming confirmed on Iceberg's multi-engine support page (`iceberg-spark-runtime-4.1_2.13`, Spark 4.1 supported from 1.11.0, 1.12.0 latest). REST fixture env var names confirmed against PyIceberg's own `docker-compose-integration.yml`.

### NOT verified, so test these first
- `docker compose build` and `up` on a real Docker daemon. The sandbox had no daemon.
- The two Maven Central downloads in the Dockerfile (`iceberg-spark-runtime-4.1_2.13` and `iceberg-aws-bundle` at 1.12.0). Maven Central wasn't reachable from the sandbox. If the build fails here, set `ICEBERG_VERSION=1.11.0`.
- The REST catalog ↔ MinIO wiring end to end (notebook 00 is the test), including `DROP TABLE ... PURGE` against the fixture (the notebooks fall back to a plain drop).
- PyIceberg reading the table via the REST catalog (`s3.force-virtual-addressing` property).
- Notebooks 00–04 against a real Iceberg catalog; the Iceberg-specific cells (`.partitions`, `.snapshots`, `VERSION AS OF`, `writeTo`) were not run.
- The optional catalog-persistence snippet in the README.

### Known limitations
1. **Catalog is in-memory** (`iceberg-rest-fixture`). Table data survives restarts in MinIO; table registrations don't. Notebooks are idempotent so re-running 01–03 recovers.
2. **MinIO image availability.** `minio/minio:latest` is used via `MINIO_IMAGE`. PyIceberg's own integration compose now uses RustFS (`rustfs/rustfs`) as the S3 store; consider switching if the MinIO image becomes a problem.
3. **Schema assumption.** Notebooks 04/05 assume the classic BTS/ASA column names. Edit the constants cell if your headers differ.
4. **Jupyter has no auth by default.** Fine on localhost; set `JUPYTER_TOKEN` otherwise.
5. **`inferSchema`** does two passes over the CSVs. Use an explicit schema for large files.
6. **Dev credentials** (`admin`/`password`) are defaults for local use only.
